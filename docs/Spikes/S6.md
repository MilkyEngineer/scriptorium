## Early conclusions (mobile)

- Image content blocks are for the **model**, not the person, on mobile: `page_image` stays useful for OCR-style questions, but anything the user must see needs a `/dl/` link (Markdown link, since bare URLs were not tappable) or a resource link.
- Tool **arguments** are small: the client would not construct a 64 KB string and stalled on 8 KB. Large inputs (documents to push, long Markdown) must come by URL (`push/fetch.py`) or in chunks; inline arguments are for short text only.
- Tool **results** of 64 KB text arrive intact.
