## Early conclusions (mobile)

- Image content blocks are for the **model**, not the person, on mobile: `page_image` stays useful for OCR-style questions, but anything the user must see needs a `/dl/` link (Markdown link, since bare URLs were not tappable) or a resource link.
- Tool **arguments** are small: the client would not construct a 64 KB string, and literals of 8 KB (mobile, Haiku) and 4 KB (web, default model) stalled it. Default inline argument cap: about 1 KB; larger inputs by URL or chunked. Large inputs (documents to push, long Markdown) must come by URL (`push/fetch.py`) or in chunks; inline arguments are for short text only.
- Tool **results** of 64 KB text arrive intact.

## Early conclusions (web)

- Resource links are not surfaced to the person at all; images are visible only inside the expandable tool panel. Neither is a way to hand a file to the user.
- The `/dl/` URL is the only cross-client delivery that works, and it is copy-paste on both web and mobile. Tools should return it as a Markdown link with a filename in the text so the model is more likely to relay it as a clickable link.
