# S0 — `remarkable-mcp` as a per-user library without AGPL dependencies

**Status:** passed (steps 1–5, 7); step 6 (device-token identity claim) **pending a live token**.
**Date:** 2026-10-17. **Fork tag:** `scriptorium-s0` = `b85bc1cc6f5a08892da24b80f9cb0bd92cc2f813` on `MilkyEngineer/remarkable-mcp`, branch `scriptorium`, based on upstream `2ad0e17`.

## Question

Can the fork of `sammorrowdrums/remarkable-mcp` be installed without `pymupdf` and `ebooklib`, instantiated per user, and used for upload with a caller-supplied UUID? If not, what do we vendor?

## Findings from reading upstream

| Area | Upstream behaviour | Consequence |
| --- | --- | --- |
| Imports | `fitz` imported at module level in `exporters.py` and `markdown_pdf.py`; lazily in `sync.py`, `extract.py`, `tools.py`. `ebooklib` lazy in `extract.py` only. | Two guards and two extras make `sync`, `extract`, `strokes` import cleanly without AGPL code. |
| Shared state | `sync.py` had no module-level mutables except a constant set; but cache dir, worker count, retry attempts/delay and cache enable were read from `os.environ` at call time, so every client in a process shared one blob cache. The module-level client lives in `api.py`, which Scriptorium does not import. | Replace env reads with a per-client config object. |
| Listing | `get_meta_items()` silently dropped any document whose index failed to download (confirms review finding 2.3). | A mirror would read a transient failure as a deletion. Needs a strict mode. |
| Upload | `upload_document()` minted a UUID and appended a root entry; a retry after a crash would create a duplicate. | Needs upsert-by-UUID and caller-supplied ids. |
| Renderer | `.rm` v6 → SVG is upstream's own code on `rmscene` (MIT); SVG → PNG and PDF page rasterising went through PyMuPDF. | Replace the rasteriser, keep the renderer. |
| Device registration | `register_device()` posts `deviceDesc: "desktop-linux"` to the desktop connect endpoint. | Parameterised; browser-style registration left for S4 to compare. |

## What the fork changes (three commits, 392 insertions / 86 deletions of code plus 349 lines of tests)

1. **`Make PyMuPDF and ebooklib optional; add permissive render backends`** — `pyproject.toml` extras `pdf`, `epub`, `tesseract`, `render` (resvg-py, pypdfium2), `full` (unchanged behaviour for `uvx remarkable-mcp`). `_svg_string_to_png` tries resvg then PyMuPDF; `_render_pdf_page_to_png` tries pypdfium2 then PyMuPDF. Output size and mode identical.
2. **`sync: per-client config, strict listings, idempotent uploads`** — `ClientConfig` frozen dataclass (`cache_dir`, `cache_enabled`, `cache_max_blob_bytes`, `sync_workers`, `retry_attempts`, `retry_delay`; `from_env()` keeps the old default). `get_meta_items(strict=, include_deleted=)` raising `PartialListingError(documents, failures)`; `load_document(entry, strict=)` raising `DocumentLoadError`; public `read_root_entries()`, `fetch_blob()`, `parse_index()`. Root commits upsert by document id; `upload_document(document_id=, page_count=)`; `upload_raw_document(document_id, files)` for pre-built xochitl files with a blob-name ownership check; `register_device(device_desc=, device_id=)`.
3. **`Add tests for embedding the client`** — an in-memory sync 1.5 store behind `_issue_request` covering separate caches, no env fallback when a config is given, strict vs lenient listing, deleted-flag handling, upsert idempotency, foreign-blob rejection, generation race retry, resvg and pypdfium2 backends.

Upstream suite: 465 passed / 10 skipped before and after; 480 / 10 with the new file. `ruff check` and `ruff format` clean. Upstreamable as the three commits above.

## Evidence (scrubbed)

- **Isolated install.** Fresh `uv` project, `uv add "remarkable-mcp[render] @ git+https://github.com/MilkyEngineer/remarkable-mcp@scriptorium-s0"`: `uv.lock` resolves to the commit above; `importlib.util.find_spec` is `None` for `fitz`, `pymupdf`, `ebooklib`, `pytesseract`, `bs4`; `remarkable_mcp.sync`, `.extract`, `.strokes` import; a 1404×1872 SVG rasterises to a 702×936 RGB PNG via resvg.
- **Licence listing** of the resolved tree (`pip-licenses`): no GPL/AGPL. `remarkable-mcp` MIT, `rmscene` MIT, `pypdfium2` BSD-3/Apache-2.0, `resvg_py` **reports UNKNOWN** because the wheel has no `License` metadata; its repository is MIT and the compiled-in resvg crate is MPL-2.0 (file-level copyleft; distributing the unmodified wheel in an MIT image is fine). The licence gate must allowlist `resvg_py` by name with this note rather than accept UNKNOWN generally.
- **Two clients, one process.** With `REMARKABLE_CACHE_DIR` pointed at a third directory, two clients with explicit configs populated only their own cache directories and the env directory was never created. Remaining `os.environ` reads in `sync.py` are confined to `ClientConfig.from_env()` helpers.
- **Idempotent upload.** `upload_raw_document` twice with the same id → one root entry, same document hash, generation advanced twice. A simulated concurrent commit between root read and `PUT /sync/v3/root` (412) is retried with the mutation re-applied and both documents survive.
- **Diff size.** Code 392+/86− (< 500); tests 349+.

## Modules Scriptorium imports from the fork

`remarkable_mcp.sync` (protocol client, `ClientConfig`, `register_device`, errors), `remarkable_mcp.strokes` (`.rm` v6 parsing and SVG generation), `remarkable_mcp.extract` (rasterising helpers only). Not imported: `api`, `tools`, `server`, `exporters`, `markdown_pdf`, `cli`.

## Decision

- **Use the fork, do not vendor.** Pin `remarkable-mcp[render] @ git+…@scriptorium-s0` in `pyproject.toml`; bump the tag deliberately. Open the three commits as upstream PRs once Scriptorium exercises them against a live account.
- Licence gate: fail on any GPL/AGPL/LGPL classifier or `fitz`/`pymupdf`/`ebooklib`/`rmink` distribution; allowlist `resvg_py` with the source noted in Architecture §4.4.
- `get_meta_items(strict=True, include_deleted=True)` is the only listing call the sync worker may use (§7 step 1 "full listing").
